### 8×V100 (32 GB)

Volta has no FP4, bf16 or FlashMLA support, so this shape is a source build of the V100 fork (`scripts/serve_hy4_flash_nvfp4_v100.sh`) rather than the Docker cells above. The Deploy panel does not emit it. It serves the [`Avifenesh/Hy4-flash-NVFP4`](https://huggingface.co/Avifenesh/Hy4-flash-NVFP4) checkpoint: NVFP4 routed experts run as W4A16 with FP16 activations, FP8 attention projections and Engram tables, FP16 KV cache. The built-in DFly drafter is on by default, and so is image and video input: the vision tower's weights stay in pinned host memory and are copied to the GPU per pass, so vision takes no KV pool. `HY4_VISION=0` serves text only.

Best measured single-session setup on 8×V100-SXM2-32GB, TP=8 with TP-sliced experts (`--ep-size 1`): DFly block 6, one running request, the full 262,144-token context (KV pool 286,720 tokens). Decode is about **197 tok/s** at temperature 0 (accept length 4.1). A tool-call turn on a cached conversation answers in about **0.24–0.27 s at 32k**, **0.30–0.36 s at 128k** and **0.37–0.38 s at 190k**; a cold prompt prefills at about **3.8–4.2k tok/s**. GSM8K 97.5% (200 questions, sgl-eval 0.1.3, temperature 0.9, top_p 1.0, default thinking).

export HY4_MODEL=/path/to/Hy4-flash-NVFP4

<Accordion title="8×V100 expanded launch (what the script runs)">

```bash Command
export TORCH_CUDA_ARCH_LIST=7.0 FLASHINFER_DISABLE_VERSION_CHECK=1 SGLANG_SKIP_SGL_KERNEL_VERSION_CHECK=1
export NCCL_ALGO=allreduce:tree
export SGLANG_SM70_FORCE_FP16=1 SGLANG_USE_SM70_FIXED_ORDER_GEMM=1
export SGLANG_DSV41_HIER_AR=1 SGLANG_DSV41_HIER_AR_CA=1 SGLANG_DSV41_HIER_AR_PUSH=1
export SGLANG_ENABLE_HEALTH_ENDPOINT_GENERATION=0 SGLANG_NUMA_BIND_V2=0
export SGLANG_GRAMMAR_DISK_CACHE_DIR=~/.cache/sglang/grammar
export SGLANG_USE_HOST_VLM_CACHE=1 SGLANG_FORCE_CPU_IMAGE_PREPROCESSING=1 SGLANG_VLM_CACHE_SIZE_MB=512

python -m sglang.launch_server \
  --model-path Avifenesh/Hy4-flash-NVFP4 \
  --trust-remote-code \
  --reasoning-parser hunyuan --tool-call-parser hunyuan \
  --dtype float16 --quantization modelopt_mixed --fp4-gemm-backend marlin \
  --mm-process-config '{"video": {"max_pixels": 33554432}}' \
  --tp 8 --ep-size 1 \
  --attention-backend dsa --kv-cache-dtype auto \
  --disable-custom-all-reduce --disable-prefill-cuda-graph --cuda-graph-bs-decode 1 \
  --max-running-requests 1 \
  --chunked-prefill-size 2048 --max-prefill-tokens 2048 \
  --warmups sampling --sleep-on-idle \
  --context-length 262144 --mem-fraction-static 0.88 \
  --speculative-algorithm DFLY --speculative-dfly-block-size 6
```

</Accordion>

<Warning>
8×V100 serves one request at a time. A second request queues, and each new subagent conversation pays its own cold prefill (about 4.5 s at 19k tokens).
</Warning>

## 1. Model Introduction

**Hy4-flash** is Tencent's ~220B-parameter (~12B active) Mixture-of-Experts model with 512 routed experts, interleaving DeepSeek-style sparse MLA attention with sliding-window attention and adding Engram n-gram memory tables.

**Available models:**

- [tencent/Hy4-flash](https://huggingface.co/tencent/Hy4-flash) — BF16
- [tencent/Hy4-flash-FP8](https://huggingface.co/tencent/Hy4-flash-FP8) — FP8 (e4m3, 128×128 block scales)

## 2. Advanced Usage

### 2.1 HiCache (Hierarchical KV Caching)

Hy4-flash supports SGLang's hierarchical KV cache, including the host-memory (L2) tier and storage (L3) backends. Toggle it in the **HiCache** card of the [Playground above](#playground) to add the flags to your launch command.

### 2.2 PD Disaggregation

Prefill and decode can run on separate SGLang instances. Pick a role and transfer backend in the **PD Disagg** card of the [Playground above](#playground); it also generates the `sgl-router` command that fronts both roles.
